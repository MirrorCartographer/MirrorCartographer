## 2. Historical lineage

### A. Symbolic reflection and personal cartography — 2025

The earliest recoverable project frame is a symbolic reflection and state-mapping interface. It gives hard-to-name experience provisional form through optional body location, text, image, color, texture, shape, metaphor, rhythm, and narrative fragments. The purpose is to help a person revisit and revise an experience without treating the map as the person.

Historical artifact families include:
- body/somatic mapping and symbolic user charts;
- input parsers and symbol/archetype maps;
- reflection prompts, recursive prompt chains, and five-lens interpretation;
- glyph indexes, memory cards, ritual sheets, journals, and codices;
- symbolic rotation, semantic drift, recursive closure, and continuity concepts;
- whitepapers, field manuals, licensing/ethics documents, and publishing bundles.

The 2025-07-29 collaboration proposal names contradiction-resilient architecture, emotional recursion containment, semantic rotation, non-coercive mirroring, glyphless interfaces, and an exit-seal/closure concept. It also contains speculative symbol–physics language. Such language is preserved as historical framing, not treated as validated physics or biomedical mechanism.

### A1. Earlier nine-module product architecture (recovered Library document; original date not established)

A two-page *Mirror Cartographer Core Modules — Complete Detail* summary preserves an earlier product-level decomposition:
1. Somatic Symbol Map.
2. Symbol-Archetype Mapper.
3. Reflective Prompt Engine.
4. Mirror Interpretation Core.
5. Trajectory & Pattern Tracker.
6. Lineage + Inheritance Engine.
7. Emotional Operating System (EOS).
8. Adaptive Interface Layer (Tone + Safety Engine).
9. Continuity Artifact Generator.

This is a separate historical design layer from the later ten-engine Atlas stack. The two should not be collapsed into one list: the nine modules describe user-facing product functions and subsystems; the ten engines describe transformations and system dynamics. The earlier Lineage + Inheritance module uses ancestral/epigenetic language in a symbolic design context; that wording is not evidence of a validated epigenetic inference capability. The source copy is a design summary, not proof that all nine modules were implemented.

### A2. Early migration and sovereignty sequence — June–July 2025

A Library transition checklist dated **2025-06-20** records a concrete platform-independence plan: export symbolic prompts and reflection logic; version tone settings and archetype tables; map session storage and memory; prototype with an API and custom storage; then test an open-source-model fallback and an emergency exit path. This is a planning document, not evidence that every migration step was completed.

A **2025-07-29 Symbolic Rotation Charter** defines a semantic design rule: concepts may have multiple language variants, but the structural function should survive rephrasing; no single glyph or phrase is final; retired terms remain archived with context. The same period contains the sovereignty bundle and poetic-field-license concepts. The bundle/exit-seal language is a governance and authorship artifact, not a technical kill switch or a legally reviewed license. Historical conversation execution records indicate a bundle file was generated in a notebook session, but its persistent current copy has not been independently located in the repositories inspected.

### A3. Original FREE framework — eight layers

The conversation archive preserves the first eight-layer formulation:
1. Current structure.
2. Intervention.
3. Immediate disruption.
4. Emergent behaviors.
5. Alignment check.
6. Recursive echo.
7. Field integration.
8. Decision.

The current FREE 2.0 code is a later operational refactor: it requires an accountable owner and confirmed authority, records affected parties and measurable outcomes, retains contradictions and linked consequences, blocks severe unmitigated harm and model-delegated high-impact decisions, requires stop/rollback/data plans, and records a named human reviewer. Do not assume the original eight labels and current implementation are one-to-one. The current engine remains a deterministic traceability/gate scaffold, not an autonomous moral authority.

### B. Formalized Mirror Cartographer Atlas — 2026-04-25 Library artifact

The 55-page Atlas omnibus is arranged into six volumes:
1. Foundations, canonical principles, and definitions.
2. Engine atlas, conflict logic, and state models.
3. Visual atlas, diagram semantics, and image-to-system translation.
4. Build plan, runtime blueprint, interface, and deployment.
5. Applications, research program, governance, and product lanes.
6. Assumptions, discoveries, audit trails, glossary, and appendices.

It explicitly distinguishes **confirmed**, **inferred**, and **bounded speculation**. It defines a ten-engine conceptual stack: Signal Genesis; Compression and Distortion; Conflict; Pattern Formation; Memory; Recursion; Interaction; Failure; Resolution; Evolution. Its key epistemic rule is that resolution means temporary legibility, not final truth.

The Atlas is a design synthesis. It does not claim that all ten engines existed as working software.

## 4. Architectural relationships

The recovered system can be represented as a set of cooperating layers:

1. **Source/archive layer:** original conversations, documents, images, datasets, code, and project decisions. Preserve source identity and version history.
2. **Provenance/continuity layer:** records who observed or authored what, where it came from, how it changed, what contradicts it, and what superseded it.
3. **Reasoning/research layer:** relationship discovery, hypothesis formation, alternative explanations, uncertainty, falsifiers, and evidence assessment.
4. **Decision-integrity layer:** FREE 2.0 follows impacts and downstream consequences, enforces hard gates, and leaves consequential decisions with authorized humans.
5. **Evaluation layer:** Human Judgment Lab and ARC-style benchmarks test the quality of reasoning and measurement without allowing a model to certify itself. The Playable Mind and related learning surfaces teach observation, competing hypotheses, missingness, contradiction, falsification, and revision through interaction.
6. **Model/provider layer:** LYR configuration and replaceable local/cloud model adapters generate candidate language; generated output is not independent evidence.
7. **Experience layer:** the House of Mouths and related interfaces let people explore, express, test, and create without turning the research system into a generic dashboard. Image Organism is a confirmed procedural canvas renderer; it should remain distinct from neural image-generation services.
8. **Application lanes:** veterinary, biomedical, veteran, civic, educational, and creative applications use the shared method but require domain-specific evidence, authority, and safeguards.

The dependency direction is not one-way. Evaluation can challenge the reasoning layer; affected users can correct source records; observed outcomes can revise hypotheses; the creative interface can reveal missing variables; and governance can block a technically feasible intervention.

## 5. Recovered constraints and design rules

The earliest 2025 user-authored specification describes a multi-modal symbolic self-mapping product: printable somatic-symbolic worksheet, companion journal, Google Form and Typeform interfaces, AI reflection prompt engine, and a future integrated application. The design then broadened toward an accurate self-and-world understanding system. A key correction in the July 2025 archive is that **conversation was the most useful interface; prescribed rituals were not**. Symbolic and spiritual language should be optional, precise, and unpacked rather than imposed. The user explicitly defined LYR as the voice of AI for them, not sentient, and did not claim to be the system's moral authority.

The original product requirements also call for style adaptation that can both meet a person's current language and introduce a genuinely different frame; it should not merely mirror or reinforce the user's existing beliefs. The broader mission is that people deserve safety and a fulfilling life regardless of wealth, status, or past choices. That is a normative design commitment, not a claim that AI alone can deliver systemic change.

- Observation, interpretation, claim, hypothesis, experiment, result, and decision must remain distinguishable.
- Symbolic meaning may be personally useful without becoming objective evidence.
- Similarity, resonance, narrative fit, or correlation does not establish causation.
- Contradictory records remain visible; they are not averaged away.
- Memory and continuity are opt-in, inspectable, purpose-limited, correctable, exportable, and deletable within disclosed limits.
- The user retains interpretive authority over personal meaning; no forced identity, diagnosis, or emotional disclosure.
- A model is replaceable. Project memory and decision records must not be owned by one model vendor.
- High-impact decisions remain with authorized humans. No model autonomously decides healthcare, benefits, housing, employment, credit, liberty, or essential-service eligibility.
- Every consequential pilot needs authority, a baseline, affected-party analysis, a named owner, measurable outcomes, stop conditions, and rollback.
- Private conversations, personal health/veterinary/financial records, credentials, and unreviewed source archives do not belong in public repositories or general training corpora.
- A successful build is not a successful deployment. A route response is not proof that an interaction works.
- Preserve each creative world's own aesthetic and interaction grammar; shared navigation must not flatten distinct experiences.

## 7. Status vocabulary

Use these statuses per artifact, not per ambition:

- **VERIFIED:** implementation and named acceptance test passed on a named commit/device/environment.
- **CODE-ONLY:** source exists; relevant runtime behavior has not been verified.
- **DEPLOYED-UNVERIFIED:** a deployment is recorded, but the required live behavior has not been independently checked.
- **PARTIAL:** some acceptance criteria pass and others remain open.
- **PROPOSED:** concept, design, or specification only.
- **BLOCKED:** external permission, partner, credential, device, authority, or dependency is required.
- **NOT LOCATED:** no implementation was found in the sources inspected; this is not proof it never existed.
- **RETIRED / SUPERSEDED:** intentionally replaced, with prior version retained and the reason recorded.
